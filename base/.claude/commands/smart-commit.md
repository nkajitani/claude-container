# smart-commit

未コミットの変更を「変更の意図」ごとに分析し、適切な粒度でコミットを提案・実行するスキル。

## 手順

### 1. 変更内容の取得

```bash
git status
git diff
git diff --cached
```

を実行して、変更ファイルと差分を把握する。

### 2. 変更の意図を分析・分類

差分の内容から、以下の観点で変更の意図を分類する：

| 意図 | 例 |
|---|---|
| `feat` | 新機能の追加 |
| `fix` | バグ修正 |
| `refactor` | 動作を変えないコード整理 |
| `config` | 設定・環境ファイルの変更 |
| `docs` | ドキュメントの変更 |
| `chore` | ビルド・依存関係・雑務 |

**同一ファイル内に複数の意図が混在する場合**は、分割せずにまとめて1コミットとして扱う（運用上の制約として許容する）。

### 3. 分割案の提示

分類結果をユーザーに提示する：

```
以下の分割でコミットを行います：

[1] feat: ユーザー認証機能の追加
    対象: src/auth/login.ts, src/auth/logout.ts

[2] config: 環境変数の設定追加
    対象: .env.example, docker-compose.yml

この順番でコミットしますか？ [y/N/編集]
```

### 4. コミットの実行

ユーザーが承認したら、分割順にコミットを実行する。

- 各コミットでは対象ファイルのみを `git add` してコミット
- コミットメッセージは `{意図}: {変更の要約}` 形式
- 全コミット完了後に結果を報告

### 5. 完了後の報告

```
✓ {n}件のコミットを作成しました。

  abc1234 feat: ユーザー認証機能の追加
  def5678 config: 環境変数の設定追加
```

## 注意事項

- ユーザーが `N` または編集を選んだ場合は、提案を修正してから再提示する
- 強制的にコミットしない。あくまで提案ベースで進める
- `git add -A` は使わず、必ず対象ファイルを個別に指定する
